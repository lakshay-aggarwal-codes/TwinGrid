# Shared limitation: synthetic training data

Every model in this system (forecaster, anomaly detector, PPO optimizer)
is trained on data generated by `src.data_generator`/`DigitalTwin` itself
— the same physics model the product simulates, not measurements from a
real facility. This means:

- Metrics (F1, RMSE, PUE improvement) measure how well each model fits
  the simulator's own physics/patterns, not real-world generalization.
- Any systematic gap between the simulator and a real facility (thermal
  time constants, sensor noise characteristics, failure modes) is
  invisible to these numbers by construction.
- This is explicitly one of the "known open issues" from the original
  handoff: real historical DC datasets (public PUE benchmarks, or a
  partner facility) are needed to calibrate the physics and validate
  these models against reality, not just internal consistency.

Report these metrics as "performance on the current simulator," not as a
claim about real-facility performance, until real data closes this gap.
